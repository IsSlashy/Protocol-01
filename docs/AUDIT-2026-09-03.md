# Self-audit, 2026-09-03

Eight readers, one per surface, each returning at most four findings with
file:line. Every finding whose severity was fund-loss, privacy or soundness
then went to two independent skeptics instructed to refute it, reading the
cited code and the path around it. A finding survives only if a skeptic could
not break it. Nothing was executed: no cargo, no vitest, no RPC. Every finding
below is a code-path argument, and the ones marked *measured* were confirmed
by a run afterwards.

Surfaces read: the prover and its AIRs, the on-chain verifier, the pool
program, the web API routes, the web client and worker, mobile and extension,
the SDKs and the pipeline, and the repository's public claims.

## The state of the protocol, in three sentences

The proof layer is the strongest part of this repository. Nothing the audit
found accepts an invalid proof or refuses a valid one: C7's leaf-equals-commitment
binding is complete and publishes no commitment (`stark/src/air/spend.rs:1084-1086`),
the lift/mask/randomiser partition is exactly consistent on all four masked
circuits, the deployed verifier agrees with the prover gate for gate on
C1/C3/C6/C7, and the phase-1/phase-2 seam cannot be straddled or borrowed
(`programs/p01_stark_verifier/src/lib.rs:135`, `:453`, `:797-801`). What was
not solid is everything written around the proofs: one web route that moved
the float's lamports authenticated nobody, the contribution bookkeeping had
two states in which a buyer who had already paid could never be handed a note,
the extension stored every note's spending secret in cleartext on disk, and
one pool state array lets a depositor write bytes nothing proved.

## Open, with what each would cost to close

**`insert_with_root_v3` writes unproved bytes that the next deposit validates.**
`programs/zk_shielded/src/state/merkle_tree_v3.rs:177` copies the caller's
`new_subtrees` into `filled_subtrees[1..=depth]` unconditionally, while
`fold_insertion` re-derives only the levels where the insertion path went left.
One honest, fully proved deposit carrying garbage in the unrestored levels
lands a value nothing proved, and because the next handler maps
`felt_from_bytes` over every entry, every subsequent shield and v3 transfer
then reverts `InvalidMerkleRoot` for ever: the pool PDA is seeded on (mint,
denomination) and there is no repair instruction, so that pool is dead for
deposits while existing notes stay spendable. The code's own comment already
calls the unbound low levels "a pre-existing hole this change narrows but does
not close"; what is new is that the hole is a permanent denial of deposits.
Remedy: stop accepting `new_subtrees` and derive the whole frontier from
`fold_insertion`. Cost: a pool-program change and a redeploy, plus one deposit
into a disposable pool to falsify it first.

**The 64-bit Merkle node.** `programs/zk_shielded/src/state/poseidon_gl.rs:172`
compresses to a single Goldilocks element, so a birthday collision costs about
2^32 hash evaluations and yields a second, never-deposited leaf whose path
reaches a published root. Confirmed as a mechanism and excluded as news: it is
already row F2 of `docs/LEAK-LEDGER.md`, priced by the ignored probe
`stark/tests/zz_skeptic_leaf_width.rs`, and named in the freeze document as one
of two open fund-loss classes blocking mainnet. It remains the largest known
hole. One document is now wrong about it: `docs/quantum-resistance.md:49` still
quotes ~85-bit collision resistance from the retired BN254 tree.

**C2 and C4 never received a mask.** `stark/src/air/confidential_balance.rs:301`:
the carry column is a two-segment step whose second segment is `owner_mint`,
and the proof publishes that column's OOD evaluation, so `owner_mint` comes
out with one field inversion. Algebra confirmed, harm killed for now: the only
consumers are `p01_zkspl` instructions whose owner is a `Signer` and whose PDA
derives from (owner, mint), so the recovered value names nothing the
transaction does not already. It becomes a live leak the moment either circuit
moves to a relayed or unsigned path, and nothing in the tree records that C2
and C4 were skipped by the masking wave.

**Downgraded but real.** `claimChallenge` carries no origin line, so a phishing
page can ask a wallet to sign it; the same capability already yields the
stealth-key derivation message, and the mitigation is advisory. `auth-sdk`'s
`verifyCallback` never consumes a session (`server.ts:132`'s `delete()` has no
call site), so a captured response replays inside the timestamp window; its
documented storeless default refuses every honest login, so nobody can be
running it that way. `pollPaymentsForRetailer` silently drops anything past 25
signatures and has no caller in the repository.

## What the skeptics killed, and the guards that killed it

A killed finding usually names a guard worth knowing about.

- **C3/C6 wasm entries take the Merkle depth from a CSV with no guard**. Killed
  because every on-chain consumer recomputes the public-input hash from a
  program constant and rejects a mismatch. The depth guard lives on chain, not
  in the wasm entry. C7's hard check at `stark/src/lib.rs:531` is still worth
  mirroring onto C3 and C6.
- **`split_note_stark` writes a caller-supplied root with no proof**. True, and
  confined to the v2 pool family whose every other instruction is commented out
  of `#[program]`. It becomes a mint the day someone ports it to v3 accounts.
- **A withdrawal sweeps its ephemeral to zero after a silent buffer-close
  failure**. Killed because the ephemeral is deterministic in (seed, pool,
  leaf), a retry re-funds it and closes the stale buffer first, and sweeping to
  exactly zero is what keeps the dirty-ephemeral check legal. Real residual:
  `recoverFloat.ts` never scans circuit 7, so a buffer stranded after a spend
  that landed has no in-app closer.
- **Both extension subscribe traps** (a retailer matched by substring, a
  bucketed 30-day interval) - killed because `handleSubscribeService` has no
  call site since the catalog moved to Discover. Both traps are still coded in
  that dead handler.
- **Mobile's encrypted store discards undecryptable state**. Killed because the
  SecureStore loss that makes the note key unreadable also takes the stealth
  seeds, so the destroyed record was already unusable. It turns a visible loss
  into a silent one.

## What this audit did not cover

Nobody read `p01_registry`, `p01_zkspl`, `p01_quantum_wallet`, `p01_relayer`,
the subscription program, the mobile UI outside the license, subscribe and
prover paths, the specter/zk/zkspl SDKs, the deploy tooling, or `stark/mvm`.

The deployed verifier's bytes were not compared to HEAD in this pass, and the
shipped wasm blob's hash was not recomputed by a reader (both are pinned by
tests that run in CI).

The false-claim findings went out without an adversarial pass, so they were
leads rather than verdicts. They are being corrected separately; the numbers
that replace them come from `docs/BENCHMARK-2026-09-02.md`, which was measured
the same week.

## Deliberately open, and not findings

Stated here so a reader does not mistake their absence for an oversight: this
is devnet only and one CLI key is the upgrade authority of both programs; the
STARK is not called zero-knowledge and its simulation argument is executed on
two witnesses at 2 queries and one at 22, with the grinding nonce and the
query-position derivation unmeasured; P6 is structural, since every transaction
has a funded fee payer; a license key is bearer material; and the note issuer
can still spend a note it issued before the holder does.
