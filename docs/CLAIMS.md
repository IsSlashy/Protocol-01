# Claims ledger for the white paper

This file backs [`docs/WHITEPAPER.md`](WHITEPAPER.md). Every sentence of the paper that states a fact about Styx carries one or more tags [K1] to [K149], and each tag is a row below that names its evidence. A fact without a row, or a row without evidence, is a defect of this file.

**How to read the evidence column.**

- **Repository paths** (`docs/…`, `programs/…`, `stark/…`, `apps/…`, `packages/…`, `scripts/…`, `tools/…`, `.github/…`) are files of this repository. A test is named as `file` (`test name`) when one test carries the fact. The first drafts of this file, written when HEAD was `6de4c8c3`, marked some paths and phrases *(uncommitted on 2026-09-23)*. Every one of them was committed later that day and is at `origin/master` `33b7888f`: `docs/BENCHMARK-METHOD.md` and `scripts/bench/*.test.mts` (`cdf4ea7a`), `LICENSE` and `LICENSE-MIT-BEFORE-POLYFORM` (`aece74aa`), the "The note blinding" section of `docs/SECURITY-LEVELS.md`, `stark/tests/next_row_openings_are_published.rs` and the marked `README.md` and `docs/HACKATHON.md` phrases (`a27f4127`). The marks were therefore removed from the rows. The run folders `docs/bench/2026-09-23/run-20260923T031450Z/` (K137, K138), `run-20260923T032635Z/` (K144, K146), `run-20260923T042841Z/` (K143, K146) and `run-20260923T051434Z/` (K145) are untracked on 2026-09-23 and must be committed with the paper. Paths under `tmp/bench-live/` (K145, K146) are the benchmark's working notes in the founder's working tree; they are never committed; they are internal logs, not yet published, available to reviewers on request.
- **`README.md` was rewritten on 2026-09-23** (`46a8e2b0`, `33b7888f`, 246 lines), and the sections and phrases the rows cite are no longer in it. Every row that cites the README therefore cites it as it stood at `a27f4127` (the audit-close docs commit), readable with `git show a27f4127:README.md`, unless the row names another commit. A reader who opens the README on GitHub will not find those phrases; they are not withdrawn claims of the project, and the current README states the same limits in shorter words (for example "Not externally audited", line 15).
- **Generated figures** come from `docs/SECURITY-LEVELS.md`, which `tools/security-levels` writes from the verifier's own source; `cargo test --locked --manifest-path tools/security-levels/Cargo.toml` fails if the document drifts.
- **Audit findings** F01 to F79 are the rows of the internal audit's findings file, `internal:audit-v1-opus/AUDIT-V1-FINDINGS.json`, described in `internal:audit-v1-opus/AUDIT-V1.md`.
- **`internal:` paths** are internal logs that do not live in the repository yet. Each such row is marked **internal log, not yet published; available to reviewers on request**. The prefix `internal:` stands for the working directory of the session that produced them (session `d5e2b253`, on the founder's machine); the full local path is withheld here because it contains the machine's user name, and is handed to reviewers with the logs.
- **Ledger rows** (B6, E3, F-b, …) are rows of `docs/LEAK-LEDGER.md`. Audit finding F03 is the same issue as ledger row F2 and as "finding F2" in `docs/SECURITY-LEVELS.md`. A ledger status "F arbre" means closed in the working tree and pinned by a passing test, **not deployed at the time the status was written**. The ledger's status column was last committed on 2026-09-20 (`195c928d`) and is stale for the web fixes of K30, K49, K120, K122 and K123: those were committed on 2026-09-20 in `2f411f33` and are live in production since 2026-09-22 (next bullet). The paper states each of them as live and not yet confirmed by a post-deploy probe (the ledger's legend counts a closure only after such a probe), and keeps open what the ledger keeps open for the extension, the mobile app or every client.
